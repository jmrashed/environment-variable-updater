# Contributing to Environment Variable Updater

Thank you for your interest in contributing to the Environment Variable Updater project! We welcome contributions from the community. Please read this guide to understand how you can contribute effectively.

## How to Contribute

### Reporting Issues

If you find a bug or have a feature request, please [open an issue](https://github.com/jmrashed/environment-variable-updater/issues) on GitHub. When reporting an issue, please include:

- A clear title and description
- Steps to reproduce the issue
- Expected behavior
- Actual behavior
- Your environment (OS, shell version, etc.)

### Submitting Pull Requests

1. Fork the repository
2. Create a new branch for your feature or bug fix
3. Make your changes
4. Test your changes thoroughly
5. Update documentation if necessary
6. Submit a pull request with a clear description of your changes

### Code Style

- Follow POSIX shell scripting best practices
- Use descriptive variable names
- Add comments for complex logic
- Ensure scripts are executable and have proper shebang

### Testing

- Test your changes on multiple Unix-like systems if possible
- Verify that existing functionality still works
- Add test cases for new features

## Development Setup

1. Clone the repository
2. Ensure you have bash and basic Unix utilities installed
3. Make the script executable: `chmod +x update-env.sh`
4. Test the script with sample .env files

## Commit Messages

Use clear, descriptive commit messages. Follow the format:
- `feat: add new feature`
- `fix: resolve issue with...`
- `docs: update documentation`

## Code of Conduct

Please adhere to our [Code of Conduct](CODE_OF_CONDUCT.md) in all interactions.

## Questions?

If you have questions about contributing, feel free to [open an issue](https://github.com/jmrashed/environment-variable-updater/issues) or contact the maintainers.
